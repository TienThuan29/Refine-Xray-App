# RAG-Pubmed Service: Schemas and Data Structures

This document describes the schemas, data structures, and "table" (collection) definitions used in the RAG-Pubmed service.

## Overview

The RAG-Pubmed service uses **ChromaDB** (a vector database) instead of a traditional SQL database. Data is stored in **collections** rather than tables. The service also uses **Pydantic models** for API request/response validation and **Python dataclasses** for internal data structures.

---

## 1. ChromaDB Collection Structure

### Collection Name
- **Default Collection**: `pubmed_articles`
- **Tenant**: `default_tenant` (ChromaDB 1.0.0+)
- **Database**: `default_database` (ChromaDB 1.0.0+)

### Collection Schema

The ChromaDB collection stores PubMed articles with the following structure:

#### Document Fields
- **id**: `str` - PubMed ID (PMID), e.g., `"12345678"`
- **document**: `str` - Combined text content for embedding:
  ```
  Title: {article_title}
  
  Abstract: {article_abstract}
  ```
- **embedding**: `List[float]` - Vector embedding generated by Gemini `text-embedding-004` model
- **metadata**: `Dict[str, Any]` - Article metadata with the following fields:

#### Metadata Schema
```python
{
    "title": str,              # Article title
    "authors": str,            # Comma-separated author names (first 3 authors)
    "publication_date": str,   # Publication date (format: "YYYY-MM-DD" or "YYYY" or "Unknown")
    "journal": str,            # Journal name
    "doi": str                 # DOI (or "N/A" if not available)
}
```

#### Example Document
```python
{
    "id": "12345678",
    "document": "Title: Diabetes Treatment Update\n\nAbstract: This study examines...",
    "embedding": [0.123, -0.456, 0.789, ...],  # Vector of floats
    "metadata": {
        "title": "Diabetes Treatment Update",
        "authors": "John Doe, Jane Smith, Bob Johnson",
        "publication_date": "2024-01-15",
        "journal": "Journal of Medicine",
        "doi": "10.1234/example.doi"
    }
}
```

## 2. Python Data Structures

### 2.1 PubMedArticle (Dataclass)

**Location**: `pubmed_rag_system.py`

**Definition**:
```python
@dataclass
class PubMedArticle:
    pmid: str                      # PubMed ID
    title: str                     # Article title
    abstract: str                  # Article abstract
    authors: List[str]             # List of author names
    publication_date: str          # Publication date
    journal: str                   # Journal name
    doi: Optional[str] = None      # DOI (optional)
```

**Methods**:
- `to_text() -> str`: Converts article to text format for embedding
  ```python
  "Title: {title}\n\nAbstract: {abstract}"
  ```

**Example**:
```python
article = PubMedArticle(
    pmid="12345678",
    title="Diabetes Treatment Update",
    abstract="This study examines the latest treatments...",
    authors=["John Doe", "Jane Smith"],
    publication_date="2024-01-15",
    journal="Journal of Medicine",
    doi="10.1234/example.doi"
)
```

## 3. API Request/Response Schemas (Pydantic Models)

**Location**: `pubmed_rag_api.py`

### 3.1 IndexRequest

**Endpoint**: `POST /crawl`

**Schema**:
```python
class IndexRequest(BaseModel):
    query: str = Field(
        ...,
        description="Search query for PubMed (e.g., 'diabetes treatment')"
    )
    max_results: int = Field(
        default=50,
        ge=1,
        le=200,
        description="Maximum number of articles to index"
    )
```

**Example Request**:
```json
{
    "query": "diabetes treatment",
    "max_results": 50
}
```

---

### 3.2 QueryRequest

**Endpoint**: `POST /query`

**Schema**:
```python
class QueryRequest(BaseModel):
    question: str = Field(
        ...,
        description="Question to ask the RAG system"
    )
    n_results: int = Field(
        default=5,
        ge=1,
        le=10,
        description="Number of relevant articles to return"
    )
    auto_fetch: bool = Field(
        default=True,
        description="Automatically fetch data from PubMed if database is empty"
    )
    auto_fetch_count: int = Field(
        default=30,
        ge=1,
        le=100,
        description="Number of articles to fetch automatically if database is empty"
    )
```

**Example Request**:
```json
{
    "question": "What are the latest treatments for diabetes?",
    "n_results": 5,
    "auto_fetch": true,
    "auto_fetch_count": 30
}
```

## 4. Internal Data Structures

### 4.1 Context Source Dictionary

**Used in**: `retrieve_context()` method

**Structure**:
```python
{
    "number": int,                 # Source number (1-based index)
    "title": str,                  # Article title
    "authors": str,                # Author names
    "journal": str,                # Journal name
    "date": str,                   # Publication date
    "abstract": str,               # Article abstract
    "relevance": float             # Relevance score (0-100%)
}
```

**Example**:
```python
{
    "number": 1,
    "title": "Diabetes Treatment Update",
    "authors": "John Doe, Jane Smith",
    "journal": "Journal of Medicine",
    "date": "2024-01-15",
    "abstract": "This study examines...",
    "relevance": 95.23
}
```

### 4.2 Retrieve Context Response

**Structure**:
```python
{
    "success": bool,               # Whether retrieval was successful
    "context_sources": List[Dict], # List of context source dictionaries
    "question": str,               # Original question (if successful)
    "error_message": str           # Error message (if failed)
}
```

## 6. Data Flow

### Indexing Flow
1. **Input**: Search query (e.g., "diabetes treatment")
2. **PubMed API**: Fetch article IDs (PMIDs)
3. **PubMed API**: Fetch article details (XML parsing)
4. **PubMedArticle**: Convert to dataclass
5. **Embedding**: Generate embeddings using Gemini
6. **ChromaDB**: Store in collection with metadata

### Query Flow
1. **Input**: User question
2. **Embedding**: Generate query embedding using Gemini
3. **ChromaDB**: Vector similarity search
4. **Context Sources**: Format results with relevance scores
5. **LLM Generation**: Generate answer using Gemini (optional)
6. **Response**: Return formatted answer with sources

## 7. Database Operations

### Create Collection
```python
collection = client.create_collection(
    name="pubmed_articles",
    metadata={"description": "PubMed medical articles"}
)
```

### Add Articles
```python
collection.add(
    embeddings=embeddings,      # List[List[float]]
    documents=documents,         # List[str]
    metadatas=metadatas,        # List[Dict]
    ids=ids                     # List[str] (PMIDs)
)
```

### Query Collection
```python
results = collection.query(
    query_embeddings=query_embedding,  # List[List[float]]
    n_results=n_results                 # int
)
```

### Get Collection Count
```python
count = collection.count()
```

### Clear Collection
```python
client.delete_collection("pubmed_articles")
# Then recreate empty collection
```

## Notes

- This service does **not** use SQL databases or traditional tables
- All data is stored in ChromaDB collections (vector database)
- The collection structure is schema-less, but follows the metadata structure described above
- ChromaDB automatically handles vector indexing and similarity search
- No migrations are needed - collections are created automatically on first use

## 9. Inspecting ChromaDB Data

### 9.1 Using the Inspection Script

A Python script `inspect_chromadb.py` is provided to connect to ChromaDB and view the data structure.

#### Prerequisites

1. Ensure ChromaDB is running:
   ```bash
   docker-compose up -d
   ```

2. Make sure you have the required Python packages:
   ```bash
   pip install chromadb python-dotenv
   ```

#### Usage Examples

**1. List all collections:**
```bash
python inspect_chromadb.py --action list
```

**2. View collection structure (displays documents in SCHEMAS.md format):**
```bash
python inspect_chromadb.py --action view --collection pubmed_articles --limit 5
```

**3. Get collection info:**
```bash
python inspect_chromadb.py --action info --collection pubmed_articles
```

**4. Export collection to JSON:**
```bash
python inspect_chromadb.py --action export --collection pubmed_articles --output export.json --limit 10
```

**5. Search collection (requires GEMINI_API_KEY):**
```bash
python inspect_chromadb.py --action search --collection pubmed_articles --query "diabetes treatment" --n-results 3
```

#### Viewing Specific Collection Structure

To view the exact structure as shown in SCHEMAS.md (lines 46-57):

### 9.2 Using Python Directly

You can also connect to ChromaDB directly using Python:

```python
import chromadb
from chromadb.config import Settings

# Connect to ChromaDB
client = chromadb.HttpClient(
    host="localhost",
    port=7000,
    tenant="default_tenant",
    database="default_database",
    settings=Settings(anonymized_telemetry=False)
)

# Get collection
collection = client.get_collection("pubmed_articles")

# Get collection info
print(f"Total documents: {collection.count()}")

# Get documents
data = collection.get(limit=5)
for doc_id, doc, metadata in zip(data['ids'], data['documents'], data['metadatas']):
    print(f"ID: {doc_id}")
    print(f"Document: {doc[:100]}...")
    print(f"Metadata: {metadata}")
    print()
```

### 9.3 Using ChromaDB HTTP API

You can also query ChromaDB directly via HTTP:

**List collections:**
```bash
curl http://localhost:7000/api/v1/collections
```

**Get collection:**
```bash
curl http://localhost:7000/api/v1/collections/pubmed_articles
```

**Query collection (requires embedding):**
```bash
curl -X POST http://localhost:7000/api/v1/collections/pubmed_articles/query \
  -H "Content-Type: application/json" \
  -d '{
    "query_embeddings": [[0.1, 0.2, 0.3, ...]],
    "n_results": 5
  }'
```

### 9.4 Troubleshooting

**Connection Issues:**
- Ensure ChromaDB container is running: `docker ps | grep chromadb`
- Check ChromaDB logs: `docker logs chromadb`
- Verify port mapping: `docker-compose.yml` should map port 7000:8000

**Empty Collection:**
- Check if data has been indexed: Use `--action info` to see document count
- Index some articles first using the API: `POST /crawl`

**Embedding Issues:**
- Ensure `GEMINI_API_KEY` is set in `.env` file for search functionality
- For viewing structure, `GEMINI_API_KEY` is not required
